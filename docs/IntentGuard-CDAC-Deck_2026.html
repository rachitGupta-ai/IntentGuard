Sovereign AI Under Siege

In 2024, the average cost of a data breach in India reached ₹19.5 crore ($2.36M). Autonomous AI agents now execute 40% of cloud operations unsupervised.

  • India's Digital India infrastructure is increasingly AI-operated — agents deploy, scale, and remediate without human confirmation
  • The command-control stack (sudoers, SELinux, PAM) was designed for human operators
  • These tools answer "is this identity allowed?" — not "does this action align with what was authorized?"
  • Sovereign AI demands accountability: AI agents on Indian infrastructure must be answerable to Indian operators

Decision Engine — Ordered Rules

Score → Action (each stage only raises restrictiveness, never lowers)

1. Tamper Override — targets engine config/process/datastore → force score=1.0, BLOCK ✗ EXIT
2. Policy DENY — admin-configured deny rule → BLOCK ✗ EXIT (pre-clamp)
3. Block-on-Access — protected target hit → BLOCK ✗ EXIT
4. Destructive Verb — rm/drop/truncate → raise score floor
5. Threshold Map — score < ask → ALLOW | [ask,block) → ASK | ≥ block → BLOCK
6. Learning Clamp — profile=LEARNING + BLOCK → downgrade to ASK
7. Agent Containment — AGENT + no human session + ALLOW → raise to ASK
8. Action Floor — most restrictive Contribution wins (raiseTo monotonic)
9. Dual-Control — PENDING → ASK, TIMED_OUT → BLOCK (distinct approver required)

System Architecture — Two Flows, One Store

A single Enforcement_Engine process. The write path enforces; a strictly read-only path serves analytics.

① Enforcement (write) path

  • Shell_Hook (UDS) blocks pre-exec until a verdict returns
  • Scoring Pipeline → Decision Engine → ALLOW / ASK / BLOCK
  • auditd feed corroborates async (1s window)
  • Persists audit + pushes SSE to the Live tab

② Read-only analytics path

  • GET /api/users · /users/{id}/profile
  • Projects 5 persisted collections into 6 activity blocks
  • Bounded 5-thread assembly, independent 5s cutoff per block
  • GET-only · no scoring/decision/translation/execution
Guarantee: a build-failing bean-wiring test proves the aggregation service can only be handed repositories — it can never reach the enforcement engine. Any non-GET verb → HTTP 405.

Innovation & Novelty

01

Intent-vs-Action Divergence Scoring

A 4-component renormalized weighted sum (sequence · context · semantic · behavioral). No existing shell-security tool scores alignment with declared intent — they only check identity/permission.

02

Per-User Forensic Profiling + Risk Score (new)

One read-only view reconstructs a user's whole story: command timeline, native-language intents, assistant queries, translations, learned behavior — plus an average command score and a 30-day risk-trend graph, computed purely from already-scored data.

03

Agent-Aware Containment

The engine distinguishes AI agents from humans. An unattended agent never gets a silent ALLOW, and risk markers (outbound + secret-access + priv-esc) monotonically uplift the score.

04

Bharat-First, Native-Script Multilingual

Intents and explanations render in the operator's own script (Devanagari, Tamil, Bengali…) beside English — technical tokens (paths, IPs, commands) preserved byte-for-byte across 11 languages.

Security & Safety by Design

Tamper-proof

  • TamperClassifier → force score 1.0, BLOCK
  • SelfDefenseGuard rejects engine-internal ops
  • PrivilegeSeparationChecker at boot

Fail-closed

  • Dependency down → BLOCK (never ALLOW)
  • ASK timeout → BLOCK
  • Dual-control timeout → BLOCK

Graceful degradation

  • LLM slow/down → Semantic excluded, 3 deterministic components still block
  • Translation down → falls back to English (HTTP 200)
  • Assist down → clean 502, never a leak
Sovereign & observational: on-prem Qwen2.5:14B — no command text, path, or telemetry leaves the network (/api/sovereignty proves it live). The profiling analytics layer is strictly read-only: GET-only, pure reads, 405 on any write, zero enforcement reach.
